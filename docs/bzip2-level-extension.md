# Does the compression level change ASan's runtime overhead?

A smaller bzip2 block changes the encoder's working set. It could change the
cost of memory-access checks relative to the uninstrumented encoder. We compare
the two endpoints, -1 and -9, at identical input size and content.

## Design

The four configurations cross compression level with instrumentation. All runs
used the same two binaries on the same Debian host. Both were compiled at -O2
with frame pointers. Only the ASan build added -fsanitize=address. Each
configuration ran once as a warmup and four times for measurement. Each
configuration occupied every position in a round once. Wall time includes process
startup and shutdown, with compressed output directed to /dev/null.

The extension was executed in a Debian sandbox using GCC 14.2. The earlier
WSL/Clang batches describe a different environment and are excluded from
this comparison. In this sandbox the upstream ASan tests initially stopped
in LeakSanitizer under tracing. We set ASAN_OPTIONS=detect_leaks=0 for every
configuration. Both variants subsequently passed the six upstream compression
and decompression comparisons. The input was generated by the original script.

## Reproduce in a fresh checkout

Use Python 3, GCC 14.2 with libasan, Make, binutils, curl and sha256sum.
The existing build wrapper accepts a compiler executable via CLANG.

```bash
export CLANG=gcc ASAN_OPTIONS=detect_leaks=0
bash scripts/build_bzip2.sh
python3 scripts/generate_input.py
python3 scripts/compare_bzip2_levels.py results/extension-levels/new-batch
```

The output directory must be new. To audit the recorded batch, see
[raw times including warmups](../results/extension-levels/batch-01/runs.csv),
[summary CSV](../results/extension-levels/batch-01/summary.csv),

## Results

Elapsed seconds are mean ± sample standard deviation (n=4); ratios divide the
ASan mean by the baseline mean at the same level.

| Level | Baseline (s) | ASan (s) | Ratio of means |
|---|---:|---:|---:|
| -1 | 3.318 ± 0.150 | 7.136 ± 0.273 | 2.150× |
| -9 | 3.521 ± 0.168 | 7.227 ± 0.013 | 2.053× |

ASan increased elapsed time at both levels. The observed ratio fell by 0.098
(about 4.5%) from -1 to -9, although the ASan binary itself took slightly
longer at -9. The baseline mean grew more, in relative terms, than the ASan
mean. Four repetitions on one synthetic input give limited evidence for a
level-dependent effect. The results support a runtime cost on this workload;
the paper's aggregate slowdown on SPEC CPU2006 remains an open comparison.
